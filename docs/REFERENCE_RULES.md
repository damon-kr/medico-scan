# 개선된 문서 참조 규칙 (4-Layer 구조)

> **목적**: 코드와 문서 간 일관성 유지, 효율적인 개발 프로세스 지원  
> **적용 범위**: 모든 코드 변경, 기능 추가, 문서 업데이트 작업

---

## 📋 작업 시 규칙 준수 체크리스트

### ✅ 코드 변경 전 필수 체크
- [ ] 변경하려는 기능이 어떤 Layer 문서에 해당하는지 확인
- [ ] 해당 Layer 문서의 최신 정보 검토
- [ ] 기존 설계 의도와 충돌하지 않는지 확인

### ✅ 코드 변경 후 필수 체크
- [ ] 변경된 코드가 문서와 일치하는지 검증
- [ ] 불일치 시 문서 즉시 업데이트
- [ ] 관련 다른 Layer 문서에 영향 없는지 확인
- [ ] 진행 상황 문서(Layer 4) 업데이트

## 🏗️ 4-Layer 문서 구조

### Layer 1: Core Architecture (핵심 아키텍처)
**문서**: `01-architecture.md`, `02-domain-logic.md`, `03-data-schema.md`

**특징**: 
- 시스템의 근간이 되는 설계 정보
- 변경 시 전체 시스템에 영향
- 가장 높은 정확성 요구

**참조 시점**:
- 새로운 컴포넌트 추가 시
- 데이터 구조 변경 시
- 비즈니스 로직 수정 시
- 시스템 구조 파악 시

**업데이트 규칙**:
- 코드 변경과 **동시에** 문서 업데이트 필수
- 변경사항이 다른 모듈에 미치는 영향 문서화
- 예시 코드는 실제 구현과 **100% 일치** 필수

### Layer 2: Process & Flow (프로세스 및 플로우)
**문서**: `04-userflow.md`, `05-implementation-guide.md`

**특징**:
- 사용자 경험 및 개발 프로세스 가이드
- Layer 1의 구조를 바탕으로 한 실행 방법
- 중간 수준의 정확성 요구

**참조 시점**:
- UX 플로우 변경 시
- 새로운 기능 개발 시
- 사용자 여정 최적화 시
- 개발 방법론 확인 시

**업데이트 규칙**:
- 사용자 플로우 변경 시 즉시 반영
- Layer 1 변경 시 연관 프로세스 검토 및 업데이트
- 개발 가이드는 실제 성공/실패 경험 반영

### Layer 3: Documentation & Context (문서 및 컨텍스트)
**문서**: `README.md`, 각종 설명 문서

**특징**:
- 프로젝트 소개 및 전체적인 맥락 제공
- 외부 사용자나 새로운 개발자를 위한 정보
- 최신성 중요하지만 일부 지연 허용

**참조 시점**:
- 프로젝트 소개 시
- 새로운 팀원 온보딩 시
- 외부 문서 작성 시

**업데이트 규칙**:
- 주요 기능 변경 시 README 업데이트
- 프로젝트 목적이나 구조 변경 시 즉시 반영
- 정기적 리뷰 (월 1회) 및 최신화

### Layer 4: Live Tracking (실시간 추적)
**문서**: `06-progress.md`

**특징**:
- 실시간 진행 상황 추적
- 작업 히스토리 및 이슈 관리
- 높은 업데이트 빈도

**참조 시점**:
- 모든 작업 시작 시
- 작업 완료 시
- 프로젝트 현황 파악 시

**업데이트 규칙**:
- **모든 작업** 시작과 완료 시 업데이트 필수
- 일일 작업 종료 시 현황 정리
- 이슈 발생 즉시 기록

## 🔄 코드-문서 동기화 프로세스

### 1. 계획 단계
```
코드 변경 계획 → Layer 1 문서 검토 → Layer 2 가이드 확인 → 작업 계획 수립
```

### 2. 개발 단계
```
Layer 4 작업 시작 기록 → 코드 구현 → 동시 문서 업데이트 → 검증
```

### 3. 완료 단계
```
코드-문서 일치성 확인 → 다른 Layer 영향 검토 → Layer 4 완료 기록
```

## 🎯 Layer별 정확성 요구사항

### Layer 1 (Core Architecture): 100% 정확성
- 타입 정의는 실제 코드와 **완전 일치** 필수
- 함수 시그니처, 인터페이스는 **실제 구현과 동일** 필수
- 예시 코드는 **복사-붙여넣기로 동작** 가능해야 함

### Layer 2 (Process & Flow): 90% 정확성
- 전체적인 플로우는 실제와 일치
- 세부 구현은 일부 차이 허용
- 개발 가이드는 실제 적용 가능해야 함

### Layer 3 (Documentation): 80% 정확성
- 전체적인 프로젝트 설명은 정확
- 세부 기술 스택이나 버전은 일부 지연 허용
- 프로젝트 목적과 주요 기능은 최신 상태 유지

### Layer 4 (Live Tracking): 실시간 정확성
- 현재 진행 상황은 실시간 반영
- 완료된 작업은 즉시 업데이트
- 다음 작업 계획은 수시 조정 가능

## 🚨 필수 검증 포인트

### 타입 정의 검증
```bash
# TypeScript 컴파일 검증
npm run build

# 타입 검사
npm run type-check  # 있는 경우
```

### 코드-문서 일치성 검증
1. **인터페이스 일치**: `types/survey.ts` ↔ `03-data-schema.md`
2. **함수 시그니처 일치**: 실제 구현 ↔ `02-domain-logic.md`
3. **컴포넌트 구조 일치**: 실제 파일 ↔ `01-architecture.md`

### 문서 간 일관성 검증
1. **Layer 1 ↔ Layer 2**: 아키텍처와 구현 가이드 일치
2. **Layer 2 ↔ Layer 4**: 가이드와 실제 진행 상황 일치
3. **Layer 3 ↔ 전체**: README와 실제 프로젝트 상태 일치

## 📚 FAQ: 자주 묻는 질문

### Q: 문서 업데이트를 깜빡했을 때는?
A: 즉시 `git log`로 최근 변경사항 확인 후 관련 문서 일괄 업데이트

### Q: Layer 1 문서가 너무 자주 바뀌는데?
A: 설계가 안정되지 않은 초기 단계입니다. 안정화 후 변경 빈도 감소

### Q: 문서가 너무 길어서 읽기 힘들어요
A: 각 Layer는 독립적으로 읽을 수 있도록 설계. 필요한 부분만 참조

### Q: 새로운 팀원에게 어떤 문서부터 보여줘야 하나요?
A: README.md → 01-architecture.md → 06-progress.md 순서 권장
